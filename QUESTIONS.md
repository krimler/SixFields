## Q1 — Project name and license

Context: CLAUDE.md lists both as must-ask. The working name `capi-distro` is in the Go
module path and the break-glass label (`capi-distro.io/break-glass`).
Options: keep `capi-distro`; pick a real name now; decide at first release.
Recommendation: keep `capi-distro` until there is something to release, then rename in one
commit — the name appears in the module path, the label domain and the CLI binary name,
and all three are mechanical to change.
Meanwhile: `capi-distro` everywhere; no LICENSE file is committed, because adding one is
the licensing decision. Every dependency added so far is Apache-2.0, MIT or BSD.

## Q2 — Recorded fixtures need a container runtime

Context: CLAUDE.md rule 4 says fixtures are recorded from real `make dev-up` runs, never
written. No container runtime is running on this machine (`docker info` fails; Docker
Desktop is installed but not started), so no fixture in `testdata/fixtures/` has been
recorded from a live cluster.
Options: (a) start Docker Desktop and record, (b) ship synthetic fixtures and re-record
later, (c) block.
Recommendation: (a), and it takes one command — `open -a Docker`, then `make dev-up &&
make record-fixture NAME=std-docker-happy CLUSTER_NAME=dev-1`. Starting a GUI application
on the human's machine unattended is not something the agent should do on its own.
Meanwhile: (b). Every fixture under `testdata/fixtures/` is generated by
`internal/fixture` and carries `_meta.synthetic: true` plus a note saying what it stands
in for. `make test` fails if a *recorded* fixture is missing its provenance, and
`TestFixtures_SyntheticAreDeclared` fails if a synthetic one is not declared. The fold,
why, eta and render tests are written so that re-recording changes fixtures only, not
assertions.
